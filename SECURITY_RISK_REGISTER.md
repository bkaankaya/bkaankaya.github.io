# Portfolio Security Risk Register

**Updated:** 5 November 2026. **Baseline:** `3e006bc` / `83ae99b` hardening review. Current release uses a static Next.js export to GitHub Pages. This document separates resolved package advisories from limitations of the hosting model.

## Verified dependency remediation

The repository owner explicitly authorized a narrow security exception to the usual no-upgrade policy.

| Component | Earlier resolved | Current resolved | Result |
| --- | --- | --- | --- |
| Next.js | 16.2.0 | **16.4.5** | October and November security fixes |
| PostCSS (direct) | 8.5.14 | **8.5.32** | Fixed CSS/source-map issues |
| Sharp (transitive) | 0.34.5 | **0.35.5** | Fixed native image processing advisories |
| nanoid (transitive) | 3.3.12 | **3.3.20** | Fixed generator advisories |
| source-map-js (transitive) | 1.2.1 | **1.2.2** via narrow pnpm override | Fixed event-loop DoS advisory |
| baseline-browser-mapping (transitive) | 2.10.27 | **2.11.0** via narrow pnpm override | Fixed invalid-input DoS advisory |

The upgrade workflow used **Node 22 / pnpm 10.11.0** and passed frozen install, TypeScript, the existing regression tests, static export, and **`pnpm audit --audit-level high` with “No known vulnerabilities found”**. Evidence: [temporary remediation run](https://github.com/bkaankaya/bkaankaya.github.io/actions/runs/42065828859). A clean scanner output is a point-in-time result, *not* evidence that all vulnerabilities are absent or that GitHub Pages is intrinsically secure.

The direct React 19 / React-DOM 19, Tailwind 4, Lucide, TypeScript and Actions toolchain versions remain unchanged. The lockfile is generated by pnpm rather than handwritten. The one-off self-updating workflow is removed immediately after the verified manifest commit; standard CI uses read-only checkout.

## Remaining security / operations risks

| ID | Surface | Status and necessary action |

## Architecture / trust boundary

The public deployed artifact is `out/`: HTML, CSS, bundled JavaScript and static images. It has no production Node server, API, authentication, cookies or database. The build toolchain **does** run dependency code, so keeping its packages patched remains important. The published artifact is scanned for secret patterns, `.map` files, malicious SVG patterns, externally loaded scripts and unsafe links.

The intentional absence of a strict CSP is documented, not described as mitigated. Every additional frontend library or remote widget requires re-evaluation of the published attack surface.
